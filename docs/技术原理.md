# 技术原理

## 1. 游戏的语言系统

ROB RUN 基于 Unity 6，使用 Unity 官方的 **Localization** 包做多语言，资源加载走 **Addressables**。

语言文本不在 DLL 里，而在一个普通的 Addressables 资源包中：

```
ROB RUN_Data\StreamingAssets\aa\StandaloneWindows64\
    localization-string-tables-english(unitedstates)(en-us)_assets_all.bundle
```

这个 bundle 里有若干 `MonoBehaviour` 资源，其中名字为 `StaticStrings_en-US` 的那个就是主文本表，字段结构：

```
StaticStrings_en-US (MonoBehaviour)
└── m_TableData: Array
    └── [i]
        ├── m_Id        : int      唯一 ID
        ├── m_Key       : string   键名（通常为空）
        └── m_Localized : string   显示文本   ← 我们改这里
```

游戏内置了 6 种语言（en / fr / de / pt / ru / es），每个对应一个 bundle。**没有中文**，所以要做的不是「新增中文语言包」而是「把英文语言包的内容换成中文」——这样游戏的英文选项就显示中文，避免去改 Addressables catalog 和 Localization 的 locale 配置（那才是真正容易翻车的地方）。

## 2. 为什么不用「新增中文语言包」的方式

理论上更优雅的做法是：

1. 往 `aa/StandaloneWindows64/` 里加一个 `..._chinese(zh-hans)_assets_all.bundle`
2. 修改 `catalog_*.bin`，注册这个新资源
3. 修改 `localization-settings` 资源，注册 `zh-Hans` locale
4. 让游戏语言列表里出现「中文」

问题在于：

- **`catalog_*.bin` 是二进制序列化格式**，手改极易破坏，且 Addressables 会校验内容哈希
- **`localization-settings` 是另一个 bundle 里的资源**，同样要重新封包
- 一旦 catalog 损坏，游戏启动时资源加载直接失败，表现是**黑屏或闪退**，玩家很难自助恢复

替换现有语言包则只动一个文件，出错也只需还原一个文件。工程上的取舍很明确：**改一个文件的风险远小于改三个文件并重建索引**。

## 3. 封包流程

```
原版 bundle
    │
    │  UnityPy.load()          读取 bundle 容器（LZ4 压缩、块信息、资源索引）
    ▼
env.objects                    遍历资源
    │
    │  obj.read_typetree()     按 TypeTree 反序列化成本地 dict
    ▼
{ m_Name: "StaticStrings_en-US", m_TableData: [...] }
    │
    │  逐条替换 m_Localized
    ▼
obj.save_typetree(tree)        按同一 TypeTree 序列化回字节
    │
    │  env.save(out_path=...)
    ▼
汉化 bundle（容器结构、压缩方式、资源索引与原版一致）
```

**关键：TypeTree 是完整的。** 有些游戏发布时会剥离 TypeTree（需要靠 IL2CPP 的 `global-metadata.dat` 重建类型信息），那样就得做字节级替换，改动长度还会破坏偏移量。ROB RUN 没有剥离，所以可以走结构化读写，改多长的中文都安全。

## 4. 翻译流程里的两个坑

### 4.1 富文本标签

游戏文本里混着 Unity 的富文本标记：

```
<color=#FF0000>WARNING</color>
```

直接丢给翻译引擎，大概率被翻成 `<颜色=#FF0000>警告</颜色>` 或标签被吃掉，游戏里就会显示成乱码或者样式崩掉。

处理方式是**先保护、后还原**：

```
保护前: <color=#FF0000>WARNING</color>
保护后: <TG0>WARNING<TG1>        ← 标签入栈，替换成序号标记
翻译后: <TG0>警告<TG1>
还原后: <color=#FF0000>警告</color>
```

### 4.2 占位符

```
Your settlement {0} is under attack!
```

`{0}` 是 `string.Format` 的占位符，被翻译引擎改成 `{0 }`、`{O}`、`{ 0 }` 都会让游戏在运行时抛 `FormatException`，表现是**该条提示不显示或整段界面空白**。

同样用标记保护（`<PH0>`），翻完用正则还原，并且还原时容忍引擎加的空格（`<\s*PH0\s*>`）。

### 4.3 多行批量

为了控制请求数，一次提交 20 行、用换行分隔。这里必须先做两件事：

- 文本内部的换行替换成 `<NL>` 标记，否则行数对不上
- 返回后校验 `行数 == 提交行数`，不等就二分递归拆分重试

## 5. 质量分层

| 层级 | 覆盖范围 | 处理方式 |
|---|---|---|
| 术语表 | 98 条界面高频词 | 人工翻译，优先级最高，机器翻译不会覆盖 |
| 机器翻译 | 剩余 4469 条 | 批量翻译，长句质量可接受 |
| 保留原文 | 195 条 | 武器型号、纯符号、纯占位符 |

术语表之所以单独成文件（`tools/glossary.json`），是因为界面词条会被玩家每天看几百遍，机翻的生硬感在这个量级下会被无限放大。比如 `Carabiner` 机翻成「卡宾枪」，实则是登山用的「快挂」；`Trunk` 机翻成「树干」，实则是「后备箱」。

## 6. 校验

`build.py` 封包后会重新加载产物，统计含中日韩字符的条目数，为 0 就直接报错退出：

```python
cjk = sum(1 for e in tree["m_TableData"]
          if isinstance(e.get("m_Localized"), str)
          and any("\u4e00" <= ch <= "\u9fff" for ch in e["m_Localized"]))
```

安装脚本也会对比复制前后文件大小，防止杀毒软件静默拦截导致装了个空壳。

## 7. 与反作弊的关系

ROB RUN 用 Easy Anti-Cheat（EAC）做内核级反作弊。本项目：

- **不修改** `ROB RUN.exe`、`Assembly-CSharp.dll`、`UnityPlayer.dll`
- **不注入**任何进程、不挂钩 API
- **只替换**一个数据资源文件

EAC 的主检测面是可执行代码签名、内存完整性和已知作弊特征，数据资源被替换通常不在其判定范围内。但这不等于零风险——如果游戏后续加入资源完整性校验（哈希白名单），替换后的 bundle 会被识别。因此项目始终保留一键还原。

如果哪天游戏因为语言包导致 EAC 报错，正确做法是：**跑一次「卸载汉化.bat」→ Steam 验证文件完整性 → 确认能进游戏**，而不是去折腾 EAC 重装。
